# v7 方案复盘：三个致命缺陷（2026-09-14）

评审对象为 `claude-a2-v7-c1` 的完整线上链路：VAD 门控、CAM++ 滑窗嵌入、跳变分段、二簇 AHC、dense rescue、碎段吸收和逐段 ASR。DeepSeek 的定性评价说明 v7 在当前观察样本中优于对照，但不足以证明泛化；现有 23 个真值文件全是双人，可信 DER 主要来自 3 个安静文件，且它们不经过救援分支。

## 1. 说话人数被强制为 2，单人守卫不是人数判断

**代码事实**：`CLUST_N=(2, 2)`，段级探测与最终 AHC 都以 `t=2` 聚类。所谓单人守卫只在 `_build_seg` 恰好产生一个代表段时返回单人；只要长单人录音因噪声、声道或音色漂移产生两个以上代表段，就会被强制拆成两人。三人以上也必然被压成两人。最终结果仍固定返回 `verdict="reliable"`。

**为何致命**：人数一错，之后所有 speaker 标签和话轮统计都失去语义。现有记录已经确认 ≥20 秒单人音频仍可能被判为两人；真实 3/4 人数据又完全缺失，所以这不是边缘情况，而是产品输入域未被实现。

**必须达到的修复标准**：先实现“1 人 / 多人 / 不确定”三态并传播置信度；不确定时禁止声称 reliable。至少用真实单人、双人和三人录音分别验收误分与漏分。

## 2. 救援门让模型自己当裁判，系统性奖励欠切

**代码事实**：`_rescue_gate` 只比较 dense rescue 与 window 回退的切换数，允许上限为 `max(1.5 * max(n_sw_win, 1), n_sw_win + 2)`。两者来自同一批 CAM++ 嵌入和二簇假设，没有独立声学证据或人工话轮信号。与此同时，`dom_ratio >= 0.95` 直接绕过救援；已知 10228/11143 正是真塌缩，却输出 35/36、29/30 个同标签段。

**为何致命**：window 基线若已经欠切，救援门就以错误基线惩罚真实切换。它能减少碎段，却无法区分“噪声过切”和“快速真实对话”，因此优化目标天然偏向少切、长段合并。DeepSeek 指出的“长段合并多”正是这一失效方向。

**必须达到的修复标准**：门控至少加入与切换数独立的证据，例如边界两侧稳定嵌入支持、最短持续时间与不确定区间；验收同时报告 false alarm 和 missed change，不能只看段数或碎段数下降。

## 3. 分离边界直接驱动逐段 ASR，却没有幻觉或失败契约

**代码事实**：`run_claude_lane` 按每个分离段重新调用 ASR，直接接受 `text`；没有 ASR 置信度、重复/幻觉过滤或与 VAD 的最终裁剪。异常只被吞掉并返回空文本。无论是否空文本、长段、低置信聚类或 ASR 幻觉，顶层都返回 `verdict="reliable"`。

**为何致命**：一个错误长段会同时损坏说话人归属和整段文本；短段反复独立解码也会丢上下文并放大非确定性。DeepSeek 已直接观察到“文本幻觉多”，而当前接口没有任何信号让调用方降级或拒绝该文本。

**必须达到的修复标准**：ASR 与说话人边界解耦，优先整轨或 VAD 句级转写后按时间对齐；保留 ASR/分离置信度并生成 `uncertain`，对无语音覆盖、异常长段和低置信文本做可测试的拒绝或降级。

## 决策

v7 可以继续作为当前双人样本的最佳基线并冻结存档，但不能作为通用说话人分离方案发布。下一版的优先级应为：人数与不确定性契约、独立边界证据、ASR 时间对齐。继续微调 `RESCUE_SWITCH_MAX` 或碎段阈值无法消除上述三项结构问题。
