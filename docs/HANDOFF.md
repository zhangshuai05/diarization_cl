## 2. 为什么这一轮是必要的

上一轮结束时，`unlocked` 的账有三个洞：

1. **收益全用 DER 说的，项目主指标（句级归属率）从没算过。**
   端到端产物 `v13_e2e_unlocked2_*.json` 的行字段只有 `base` / `fixed`，都是 DER。
   句级主指标只在**粗窗代理**上跑过，而代理↔真实路径的关系自认 n=3、未验。
2. **`min_win=2` 是在全部 20 场（dev+holdout）上选的**（源码 docstring 自己写了
   in-sample tuned），但没人测过相邻档位。
3. **交付表说"剩下 84% 是聚类质量/嵌入可分性问题"** —— 这是**假设**，
   而它同时是"换 VBx/PLDA"唯一的立项理由。

于是定了三步：① 补主指标 + `min_win` 敏感性（判"落地/不落地"）
② train_L 残差归因（判"要不要换后端"）③ 按②的结论决定。
**顺序是先测再改。**

## 4. ★ 结论 ②：残差归因翻转 —— "剩下是聚类可分性问题"不成立

### 4.1 train_L 那 20 场（`>40%` DER）里，18 场 k 还是明显偏小

数据源：`artifacts/v13_e2e_unlocked2_all_mw2_objective.json`（30 场，字段很全：
`miss/confusion/false_alarm` 三项分解 + `k` + `eff_k` + `n_ref_speakers`）。

| 事实 | 数值 |
|---|---|
| 交付表「`>40%` 的场次 20/30」 | ✅ 复现 |
| 交付表「占解锁后总残差 84%」 | ✅ 复现（按 DER 总和 84%；按场次占比是 67%，两个口径都没错） |
| **`fixed k < eff_k`** | **18 / 20**（差 1~4，典型：`2<4`、`3<7`、`4<7`） |
| `fixed k > eff_k` | 0 |
| miss | **≤2.2%**（全 20 场） |
| confusion | 33%–68%（主导） |
| false alarm | 6%–30% |

⇒ 残差几乎全是 **confusion**，且 **k 根本没选够**⚠（这个判断的比较基准有疑点，见 4.2(b)）。
交付表把「7.6 点」读成"k 选择在这个 cohort 上的**总可修复空间**"——
**那是误读**：7.6 点是**当前 unlocked 规则实际捡到的**，不是上限。

### 4.2 ⚠️ 更正：上一版「dev 的可分性其实不差」是我读错了

上一版这里写「窗内无「家」的说话人 = **0**」并引出「给对 K 就分得挺干净」。
**那个推论不成立**，两处都有问题：

**(a) 「有家」这个指标看不见合并。** 判据是 `share_in_home >= 0.5`——
**两个说话人并进同一簇时，两边的 share 都≈1.0、都得满分。** 去重后的家簇数才是真的。

| 场次 | 真K | 报"有家" | **去重后家簇** | 合并 |
|---|---:|---:|---:|---|
| dev `M_R003S04C01` | 4 | 4 | **2** | c3=[004-F, 005-F, **006-F**] |
| dev `M_R003S05C01` | 4 | 4 | **2** | c3=[004-F, 005-F, 006-F] |
| dev `L_R003S04C02` | 2 | 2 | **1** | c1=[005-M, 006-M] |
| dev `L_R003S01C02` | 4 | 4 | 3 | c2=[005-M, 006-M] |
| dev `L_R003S02C02` | 3 | 3 | 2 | c2=[005-M, 006-M] |
| dev `L_R003S03C02` | 3 | 3 | 2 | c1=[005-M, 006-M] |

**dev 12 场里 6 场如此，全部被报成满额"有家"。** 所以"无家的说话人 = 0"
数字本身对，但**不能**用来支持"可分性不差"。

**(b) 「正确 K」的基准偷用了被禁的假设。** 4.1 用 `eff_k` 判"k 偏小"，
那正是 §9 里**不得引用**的「K 应等于真值人数」，只换了 5% 阈值。而 §C 的物理边界说
短发言者 60% 没有纯窗、**15% 在窗内从未出现**——所以 `k < eff_k` 部分是**预期行为**。
v2 探针新增的 `speakers_visible` 把这件事显式化（如 `20200706_L_R001S07C01`
真 K=7 但**只有 5 个说话人在窗内出现过**）。

⇒ **更正后的说法：真 K 下 dev 也有 6/12 场合并、最差簇纯度低到 0.39 ⇒ 可分性在 dev 上同样没被证明。**

### 4.3 ★ 三场 train_L 实测：**免真值判据一个都选不中真 K（0/9）**

新增 `criterion_curve` / `criterion_picks`（`probe_truek_purity.py` 已修成 v2）：
同一份 embedding 上，把**现行免真值判据**（`unlocked_selector.build_unlocked`，
与生产候选表同一份实现）在整条 k 网格上的读数打出来，看真 K 是不是它的极值。

| 场次 | 真K | **窗内可见** | 实得簇 | 空簇 | v12 选 | 最差簇 | 有家 | **去重家簇** |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| `20200706_L_R001S07C01` | 7 | **5** | 7 | 0 | 3 | 94.6% | 5/7 | 4 |
| `20200708_L_R002S02C01` | 7 | 6 | 7 | 0 | 3 | 56.9% | 6/7 | 5 |
| `20200709_L_R002S07C01` | 6 | 6 | 6 | 0 | 2 | **40.0%** | 6/6 | 4 |
| **免真值判据选中** | | | | | | | | |
| 　`argmax 目标函数` | 理想→真K | | | | | | | 3 ✗ / 3 ✗ / 2 ✗ |
| 　`argmax 轮廓` | | | | | | | | 4 ✗ / 5 ✗ / 7 ✗ |
| 　`最大合格 k` | | | | | | | | 10 ✗ / 10 ✗ / 10 ✗ |

**免真值判据选中真 K 的次数：0 / 9。** v12 选 K 命中 **0 / 3**。
`最大合格 k` 三场全 = cap 10 —— 它是常数，不是判据（与交付表 §D 一致）。

⇒ **纯度只说明「知道 K 时几何可分」，不说明「存在一个不读真值的量能选出这个 K」。**
「纯度高 → 改判据便宜」这一步没有依据。真正在决定 k 的是别的东西——见 4.4。

（附：`fcluster(maxclust)` 本次三场都真生成出了目标簇数、空簇 0，所以
「空簇被记成纯度 0」这个坑**这三场没触发**；但它是活的，已修。见 §8 坑 13。）

### 4.4 ★★ 真正在决定 k 的是 `MULTI_K_PENALTY`，而生产值 0.015 偏大

`build_unlocked` 的目标函数是 `objective = silhouette − 0.015·(k−2)`。
看 `20200709_L_R002S07C01` 的曲线：

```
  k :  轮廓     目标函数
  2 :  0.2716    0.2716   ← 目标函数极大值在 k=2
  6 :  0.2938    0.2338   ◀真K
  7 :  0.3144    0.2394   ← 轮廓极大值在 k=7
 10 :  0.2786    0.1586
```

**轮廓全网格跨度只有 0.099，而惩罚项走 8 步就是 0.12 —— 惩罚比整个信号还大。**
⇒ 轮廓选 7（真 6），被惩罚拖到 2。**在轮廓曲线平坦的场次上，是常数项在选 k。**

dev 主指标上的惩罚扫描（`probe_unlocked_sentence.py --penalty`，缓存口径，秒级）：

| penalty | 主指标 | vs base | 改善/恶化/持平 | 与生产值的差异 |
|---|---:|---:|---|---|
| 0 | 84.7% | +10.8 | 4 / **1** / 7 | 松过头：`L_R003S04C02` 84.0→82.3、`M_R003S05C01` 94.7→93.0 掉分 |
| **0.005** | **84.9%** | **+10.9** | **3 / 0 / 9** | **严格占优**：只多动 `L_R003S03C02`（k 3→6，60.2→**85.5%**），其余 11 场逐位不变 |
| 0.015（生产） | 82.8% | +8.8 | 2 / 0 / 10 | 基准 |
| 0.03 | 72.6% | **−1.4** | 1 / **1** / 10 | 过紧，翻负 |

⚠️ **这是 dev 样本内扫描**（λ 与 `min_win` 都在 dev 上选的），有效 excursion 只有 3 个。
**不得**当成可落地结论；但"λ 是个活的旋钮、且生产值偏大"这件事有曲线作证。

### 4.5 ★ λ=0.005 在 train_L 上**方向复现**（唯一没被调过的 cohort）

做法：先用 `build_probe_cache.py --root <train_L> --meetings ...` 建窗缓存
（约 8 分钟/场，一次性），之后 λ 扫描就是**秒级**——不必再给每个新问题写代码，
`probe_unlocked_sentence.py` 加了 `--root` / `--meetings` / `--tag` 就能直接跑。
主窗数已与 `probe_truek_purity` 独立报的 `n_windows` 逐场核对：188 / 399 / 542 ✓

| 场次 | 真K | 可见 | base | λ=0.015（生产） | **λ=0.005** | λ=0 | λ=0.03 |
|---|---:|---:|---:|---|---|---|---|
| `20200706_L_R001S07C01` | 7 | 5 | 43.9% | k=3 43.9% | k=3 43.9% | k=4 **45.5%** | k=3 43.9% |
| `20200708_L_R002S02C01` | 7 | 6 | 40.4% | k=3 40.4% | k=5 **60.6%** | k=5 60.6% | k=3 40.4% |
| `20200709_L_R002S07C01` | 6 | 6 | 34.1% | k=2 34.1% | k=7 **64.3%** | k=7 64.3% | k=2 34.1% |
| **均值** | | | 39.5% | 39.5%（**+0.0**） | **56.3%（+16.8）** | 56.8%（+17.3） | 39.5%（+0.0） |

**三条读法：**

1. **生产 λ=0.015 下，unlocked 在这三场完全无效**（0/0/3，+0.0）——与交付表
   「train_L 只有 7.6 点、13/30 场 k 根本没变」一致。**是 λ 在拦，不是门在拦。**
2. **降 λ 后变成 +16.8**，两场大涨（+20.2 / +30.2），零回归。
   **方向与 dev 同向，而且这是一个没被调过的 cohort。**
3. 零计算的算术重算（`objective = score − λ(k−2)` 直接从已有的 `criterion_curve` 重算）
   **逐场命中实跑结果**（k=3/5/7）——以后扫 λ 不必先跑模型（注意 `score` 存成 4 位小数，
   近平局的场次会不可靠：`20200708` 的 margin 就是 0.000）。

⚠️ **这个 +16.8 不是 cohort 效应估计**：这三场是我按「k 差最大」**挑**出来的
（**按结果取样**）。它的价值只在**方向**，不在幅度——
**幅度与全 cohort 的权威读数见 4.6（+11.9 / 30 场）**。
⚠️ λ=0 与 λ=0.005 在这三场分不出高下（修的是一同两场），但 dev 上 λ=0 有两场回归
⇒ **留在 0.005**（dev 对下行风险有更多证据）。
⚠️ 该 cohort 弃权率 11.2%（dev 是 2.2%），更难。

### 4.6 ★★ 全 train_L（30 场）复验：λ=0.005 的收益**接近翻倍，零回归**

先出了「字典序前 13 场」的预指定结果（+10.8，7/0/13），但那 13 场**全在 R001 房间**
（字典序把房间聚在一起了）。建缓存实测只要 **77–660 秒/场**，索**把全部 30 场建完**，
结论就不再依赖任何预指定论证：

| cohort | n | 生产 λ=0.015 | **λ=0.005** | λ=0 | λ=0.03 |
|---|---:|---|---|---|---|
| dev（test） | 12 | +8.8（2/0/10） | **+10.9（3/0/9）** | +10.8（4/1/7） | −1.4（1/1/10） |
| train_L R001（预指定） | 13 | +5.8（3/0/10） | **+10.8（7/0/6）** | +13.1（10/1/2） | +5.1（3/0/10） |
| **train_L 全部** | **30** | **+7.0（10/0/20）** | **+11.9（16/0/14）** | +13.9（20/1/9） | +5.2（8/1/21） |

（括号内 = 改善/恶化/持平；数字均为 unlocked `min_win=2` vs 生产 base）

**四条读法：**

1. **三个 cohort 同向**，其中 **train_L 的两个（n=43）完全没参与过 λ 的选择**。
2. λ=0.005 在 train_L 上把生产 λ 的收益从 **+7.0 拉到 +11.9**，改善场次
   10 → **16**，**零回归**（vs 生产的 0/20 也一样）。
3. **λ=0.03 在 train_L 上比生产值还差且出现回归**（+5.2，1 恶化）
   ⇒ 这个旋钮**两侧都会翻车**，生产值 0.015 不在最优位置。
4. λ=0 总是均值最高（+13.9）但**两个 cohort 各出现回归** ⇒ **停在 0.005**。

⚠️ **副产物一个值得单独看的事实**：train_L 的 **base 弃权率 18.2%**（dev 只有 2.2%），
单场最高 49.1%。**五分之一的句子根本没有任何预测覆盖它**——这是一个
与选 K 无关的失败面，比 λ 更值得单独立项。

⚠️ 仍然是 **`min_win=2` 与 λ 一起比 base**（与 §3 同口径）。λ 单独贡献多少、
`min_win` 单独贡献多少，**本表不回答**。

不是 5 个独立证据。因此“平台”应理解为**安全区间内的重复采样**，不是每个格点
都提供了新的决策证据。
⇒ 这不是"0.005 这个魔法数"，而是**生产值 0.015 比安全区间大了 2–5 倍**；
落地预期也不能只报均值，train_L 全量应写成 **+11.9 均值 / +5.8 中位**，
且改善集中在少数场次（最大 +46.0，最小 0.0）。
（λ=0 才出现回归：dev 1 / train_L 1 ⇒ 下边界在 (0, 0.003]。取 0.005 而不是 0.003
是拿回一点收益、换一点余量。）

### 4.8 合起来

「解锁后剩 84% 残差、其中 84% 与 k 无关、剩下是聚类质量/嵌入可分性问题」
——这条链**中间那一跳没有证据**，且两端都与现有数据冲突。
**因此第 3 步（VBx/PLDA）现在不立项。**

但**理由和上一版不同**：不是"几何分不开"，而是**现行选 K 判据在真 K 上没有极值**（0/9），
外加一个尺度过大的线性惩罚在平坦曲线上抢决策权。前者正是 VBx 这类
**自带 K 估计**的后端要解决的问题——但它贵，且 `train_L` 上还没验过 λ。

⚠️ **限定**：4.1/4.3 是 train_L（另一 cohort：只有 L 房间、全 C01、有效 K 中位 5），
4.2/4.4 是 dev（test cohort）。两边混用时必须标 cohort。

### 坑 2：`probe_e2e_unlocked2.py --limit N` 会**静默覆盖整批产物**

输出名不含 `--limit`，所以"跑一场看看"会把 12 场的产物写成 1 场。
**本会话真踩了**（`v13_e2e_unlocked2_dev_mw2_objective.json`），已用 `git checkout` 还原。
已修：限量跑改写 `<name>_limitN.json`。**但**：修复前若你已经覆盖了，产物只能从 git 恢复。

### 坑 3：探针路径**不能**用来算 DER

`probe_path_equiv` 的等价结论**只覆盖句级**：段级几乎 100% 不同（`597/597`），
差异被下游"取最长重叠"完全吸收。所以：

- ✅ 句级归属率：探针与 `v12.diarize()` 逐位一致
- ❌ DER / 段级数字：**不适用**，必须走真实路径

### 坑 4：交付表"7.6 点 = k 选择的总可修复空间"是**误读**

7.6 是**当前 unlocked 规则实际捡到的**，不是上限。
证据：那 20 场里 18 场的 k 仍明显小于有效 K。
**凡"总可修复空间"这类上限陈述，必须有"把旋钮拧到底"的对照，否则只是已实现收益。**

### 坑 5：跨源 selfcheck 比单源自检有用

`probe_unlocked_sentence.py --selfcheck` 拿**真模型产物**核对缓存路径选出的 k，
一跑就抓到 `S_R004S01C01` 的 `5≠4`——顺藤摸到"产物是修复前的、从没重跑"。
**新探针要跟一个独立来源对账**，别只跟自己比。

### 坑 6：`.gitattributes` 的 `* text eol=lf` 会把二进制写坏（前一轮的，仍然有效）

`git status` 里的 `M` 可能是 eol filter 的**假阳性**：磁盘内容与 HEAD 逐字节相同。
**千万不要 `git add -A`**——那会把 150 个 png 真写坏。
判断"是否真被改坏"的**唯一可靠方法**是逐字节 `cmp`：
`git cat-file blob HEAD:<path> > /tmp/a && cmp /tmp/a <path>`。
**不要**用 `git status` 或 `git hash-object` 判断（它们受 eol filter 影响，报假阳性）。
检查/修法已提交在 `44be9fc`（18 类扩展名标 `-text`）。
现在根目录（`.gitattributes`）已有 `-text` 清单，**新增二进制类型要记得加进去**。

### 坑 7：动索引的命令（`read-tree` / `reset` / `update-index`）先确认状态

`git read-tree --empty` 会**清空暂存区**，把之前的归档改名全变成未暂存；
随后的 `git reset --mixed HEAD` 又彻底取消暂存。要造临时提交，
用 `GIT_INDEX_FILE` 指向**临时索引文件**，完全不碰真实索引。

### 坑 8：`fcluster(maxclust)` 的簇数可能**少于** k（不会多于）

簇数 < k → `sizes = [... for l in range(k)]` 尾部补 0 → `min(sizes)=0` → 判不合格
（行为上合理，保守拒绝）。**埋着的雷**：`sizes` 长度是 `k`，而 `_silhouette` 的
`groups` 长度是**实际簇数 m**，m<k 时两者长度不一致——现在被"不合格 → `score=-1.0`"
掩盖。**一旦放宽 `eligible`（`unlocked_selector` 的 `core` 过滤正在做这件事），这个雷会炸。**
（探针侧的同源版本见坑 14：那里已经把空簇单列，不再污染纯度。）

### 坑 9：`_silhouette` 有一处潜在索引 bug

`own = labels[index]`（簇标签**值**）而 `other = min(... enumerate(groups) ...)`（**序号**），
只在标签恰好是 `0..m-1` 时等价。而 `v12_aishell4.silhouette` 用的是另一套 `group_of`
映射——**两份实现不一致**，而"生产 vs 基准"的可比性依赖它们一致。

### 坑 10：`_candidate_clusters` 的 `max_speakers` 是 `def` 时绑定的默认参数

`_v11_window_params` 改的是**模块变量** `v11.MAX_SPEAKERS`，**改不动已绑定的默认参数**。
v12 必须在两处调用点**显式传参**。回归：`tests/test_k_cap_dispatch.py` 必须报红。
（`977fc6b` 就是修这个；修完**所有旧指标作废**，见卡点 3。）

### 坑 11：`merge_dups` 前必须先 `classify_dup`

`merge_dups` 读 `is_dup` 字段。传全 `False` 的 dict 会让 merged 列与 oracle 列
**逐位相同、静默失效**。`probe_rule_ruler.py` 的 selfcheck 已加断言锁死。

### 坑 12：读汇总列必须逐行核

前几份交替代这条付出过三次代价。**本轮的正面例子**：§3 的 `+8.8` 均值看着像普涨，
逐场拆开是 **2 场改善 / 0 恶化 / 10 持平**；§4.4 的 λ 扫描也是靠逐场差异
才看出"0.005 只多动一场、其余逐位不变"。

### 坑 13："有家"（`share_in_home >= 0.5`）**看不见合并**

两个人并进同一簇时，两边的 `share_in_home` 都≈1.0、都得满分，`speakers_with_own_cluster`
照样报满额。dev **6/12 场**如此（`M_R003S04C01` 更是一簇吞三人）。
**一律同时看去重后的 `n_distinct_home_clusters`**，别看 "有家" 单项就下"分得干净"的结论。
（同一类的错：`worst_cluster_purity` 把**空簇**记成纯度 0——见下一条。）

### 坑 14：`fcluster(maxclust)` 的簇数可能少于 k，而空簇曾被当成"很脏的簇"

`cluster_rows` 原先对 `range(k)` 里每个簇都建一行，空簇记 `purity = 0.0`；
`worst_cluster_purity = min(purity)` 于是把**「簇数不够」读成「簇很脏」**——
而这正是"改判据 vs 换后端"的判别量。已修为 v2：空簇单列
（`n_empty_clusters` / `reached_target_k`），**不进纯度统计**。

⚠️ 已存的 `v13_truek_dev.json` 是 **v1**，但实测 dev 12 场**恰好都没触发**（簇数全=真K、0 个 0 纯度簇），
所以那份的数仍然有效；train_L 的三场也是空簇 0。**它是活的坑，不是已经炸过的坑。**

### 坑 15：目标函数里那一项常数，可能比整个信号还大

`objective = silhouette − MULTI_K_PENALTY·(k−2)`，λ=0.015。
在轮廓曲线平坦的场次上，轮廓全网格跨度（0.099）**比惩罚项（0.12）还小**——
于是极大值被常数拖到低 k。**看到"选 K 偏爱小 k"时，先量惩罚项与信号量级，
再去怀疑聚类质量。** 扫 λ 是秒级的（`probe_unlocked_sentence.py --penalty`）。

### 坑 16：后台长任务**会被外部杀掉**，而日志里不会有 traceback

**没有异常**（被杀，不是崩溃）。另外 `setsid` 在 Git Bash 里**不存在**

- 长任务：`nohup ... > /tmp/x.log 2>&1 &` + **定期轮询 `ps`**，不要一次 sleep 到底。
- 判断"是不是被杀"：日志无 traceback 但进程没了 = 被杀（不是 bug）。

也在调同一个声纹模型。它跑着时，本探针单场耗时从 **77 秒抖到 678 秒**（9 倍）。

### 坑 18：先把便宜的问题问完，再去建缓存

本轮差点为了一个**纯算术**能答的问题（λ 会选哪个 k）去重建缓存——
`objective = score − λ(k−2)` 完全可以用已有的 `criterion_curve` 重算，
**逐场命中实跑结果**。之后又把"附近是不是尖峰"也用秒级扫描答了。
**先看手上已有的产物能不能算出答案**，再决定要不要花 20–100 分钟跑模型。
